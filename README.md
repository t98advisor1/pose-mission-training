# 온몸으로 찰칵! 포즈 챌린지

처음 방문하면 **직접 넘기는 13장 사용 매뉴얼**을 엽니다. 카메라 준비, 파란·초록 연결선과 2초 유지, 기본 포즈 사진 7개와 관절 힌트, 전신 보너스, 개인정보와 TOP10, 예비 연습을 안내합니다. 다음·이전 버튼, 페이지 점, 키보드 좌우키와 터치 넘기기를 제공합니다. 닫은 뒤에는 첫 화면의 통통 튀는 🤪 ‘처음이세요?’ 버튼으로 다시 볼 수 있으며 기기의 동작 줄이기 설정에서는 애니메이션을 끕니다. 닫음 여부만 브라우저에 저장합니다.

상단 사진은 작은 썸네일 대신 **크게 넘겨 보는 사진 캐러셀**입니다. 사진 전체를 잘리지 않게 표시하며 화살표와 옆으로 밀기로 7개 포즈를 살펴봅니다. **전체 화면으로 미리 연습하기**는 닉네임 없이 열리고, 원하는 기본 포즈나 전신 보너스를 선택해 같은 자세를 반복 연습합니다. 연습 성공은 새 도전·점수 저장을 호출하지 않습니다. 연습 중에도 사진/안내 다시보기·일시정지·얼굴 장식·안내 보기·연습 마치기를 제공하며, 실전 게임으로 돌아오면 원래 저장 흐름을 사용합니다. 이전 실전의 저장 대기 결과는 연습 중에도 원래 도전 정보로 재시도할 수 있지만 연습 결과로 표시하지 않습니다.

연습 추가는 경험 엔진 기존 **87개 + 새 연습 37개**, 전신 기하 **33개**, 실제 저장 연결과 연습 엔진 결합 **6개**, 합계 **163개** 검사를 통과했습니다. 브라우저에서 첫 매뉴얼, 사진·힌트 로딩, 마지막 텍스트 보너스, 390px 세로 폭, 전체 화면 연습 진입과 카메라 준비 중 종료를 확인했습니다. 현재 노트북에는 카메라가 없어 실제 휴대폰의 연습 자세 인식은 미검증입니다.

시작 화면에 **‘가족과 함께 도전해보세요!!’** 문구와 『교사와 학부모를 위한 바이브 코딩』 책 표지 아이콘을 표시합니다. 표지 아이콘은 [사용자가 지정한 교보문고 도서 페이지](https://product.kyobobook.co.kr/detail/S000220363390)로 연결되며, 해당 페이지에서 확인한 대표 이미지(ISBN 9791199560062)를 원본 비율로 사용했습니다. 모든 화면 하단에는 ⓒ 표시와 기존 저작권 문구가 나옵니다.

시작·결과 화면은 기존 TOP5와 **TOP10 보기** 버튼을 제공합니다. 펼친 목록에는 서버가 반환한 실제 참가자 최대 10명을 표시하고, 10명보다 적으면 실제 인원을 안내합니다. 닉네임별 최고 기록을 기준으로 하며 같은 점수는 공동순위입니다. 열린 목록도 실시간으로 갱신되고 게임 중에는 랭킹 표시와 갱신을 멈춥니다. 2026-10-09 읽기 전용 API 확인 당시 실제 참가자는 7명이었습니다. TOP10 확인을 위해 가상 참가자를 추가하지 않았습니다.

TOP10 수정은 기존 저장 연결 59개와 새 화면 동작 14개, 합계 **73개** 및 서버 결합 **4개** 검사를 통과했습니다. 로컬 실제 브라우저에서 Google Sheets API의 7명 목록, 열기·닫기·ESC, 390px 세로 폭의 표지·썸네일·문구·랭킹 표시를 확인했습니다. 이 확인은 실제 휴대폰 카메라·포즈 인식 시험을 대신하지 않습니다.

Gemini에서 실제 생성한 HTML·JavaScript와 수정 응답을 조립하고, Codex가 전신 보너스·저장 연결과 일부 판정·카메라 취소 처리를 후속 보완한 교원연수용 앱입니다. 생성 원문과 보완 이력을 구분해 보존했습니다. 상단에 승인된 AI 사진 7개를 큰 캐러셀로 보여 주고 큰 V·머리 위 하트·한손 브이·엄지척·양손 꽃피우기·슈퍼히어로·가벼운 댑을 차례로 진행한 뒤 마지막 전신 보너스에 도전합니다. 기본 자세를 연속 2초 유지하면 미션마다 한 번 100점을 주고 다음 미션으로 자동 진행합니다. 화면의 ‘양손 꽃피우기’는 기존 ‘꽃받침’ 미션의 안내 이름이며 API·Google Sheets 헤더는 `꽃받침`을 유지해 기존 기록을 보존합니다.

기본 포즈 사진과 관절 연결선 힌트를 크게 약 2초 보여 준 뒤, 휴대폰 세로 화면과 컴퓨터 가로 화면에 맞춘 큰 카메라 영역에서 진행합니다. 기본 7개의 힌트 SVG는 승인된 AI 사진을 실제 MediaPipe IMAGE 모드로 분석한 관절 위치에서 만들었습니다. 전신 보너스 단계는 사진 없이 **‘가장 많은 관절로 파이프를 구성하면 받을 수 있는 보너스 점수!!’**라는 문장으로 안내합니다. 이전 전신 SVG는 개념 그림으로 보존하며 이번 전신 안내에 실제 사진처럼 사용하지 않습니다. 카메라 위쪽에는 이모지와 짧은 안내가 나오고, 몸을 찾으면 파란 연결선, 목표 자세와 일치하면 초록 연결선과 유지 시간이 표시됩니다. 사진 다시 보기와 일시정지를 제공하고, 실시간 명예의 전당은 시작 화면과 결과 화면에서 확인합니다.

얼굴 장식은 빨간 사슴뿔, 빛과 음영으로 입체감을 준 빨간 코 공, 분홍 볼터치입니다. 얼굴을 따라 움직이며 장식 버튼으로 켜고 끌 수 있습니다. 게임 시작부터 종료까지의 경과 시간을 화면에 계속 표시합니다. 경과 시간은 사진 예고·일시정지 시간도 포함한 실제 흐른 시간이며 화면 표시용으로만 사용하고 서버로 전송하거나 저장하지 않습니다.

기본 점수는 최대 700점입니다. 새 기본 미션 성공에는 25% 확률로 10·20·30점의 이벤트 보너스가 붙도록 서버가 도전ID와 미션 이름으로 계산합니다. 기본 7개를 완료한 뒤 전신 자세를 연속 2초 유지하면 한 번만 100·200·300·400·500·600·700점의 7등급 중 하나를 받습니다. 얼굴을 제외한 몸 관절 22개를 대상으로 화면에 보이는 관절과 팔다리를 펼친 크기를 함께 확인합니다. 관절이 많이 보인다는 이유만으로 최고점을 주지 않으며 필요한 관절과 최소 펼침 조건을 충족해야 합니다. 자연스럽게 서 있기만 해서는 보너스를 받지 않습니다. 연속 2초 구간에 나온 등급 중 가장 낮은 등급을 확정하므로 700→500→700점이면 500점입니다. 자세 조건이 깨지면 유지 시간과 임시 등급을 다시 시작합니다.

최종 점수는 **기본 점수 + 이벤트 보너스 + 전신 보너스**입니다. 같은 기본 미션을 다시 보내도 가산하지 않고, 전신은 첫 확정 점수를 유지해 다른 등급으로 재전송해도 더하지 않습니다. 전신에는 별도 랜덤 이벤트 보너스를 붙이지 않습니다. 앱은 성공 직후 예상 점수를 보여 주며, 저장 완료는 Google Apps Script의 영수증을 확인한 뒤 표시합니다. 서버에 먼저 저장된 전신 점수가 예상과 다르면 서버 값을 반영합니다. 랭킹은 서버가 계산한 닉네임별 최고 최종 합계 점수를 읽습니다.

카메라 영상·촬영 사진·인식한 관절 좌표는 저장하거나 서버로 보내지 않습니다. 사슴뿔·코·볼터치도 기기 안에서 카메라 화면에만 그립니다. POST 항목은 `challengeId`·`nickname`·`mission` 세 가지이며, 전신도 `전신 보너스 100`부터 `전신 보너스 700`까지 100점 단위 미션 이름 중 하나로 보냅니다. 별도 점수나 관절 정보를 보내지 않습니다. 시트에는 미션별 점수·기본 점수·이벤트 보너스·전신 보너스·최종 합계·갱신시각을 기록합니다. 저장 대기 결과는 브라우저에 보관해 재시도합니다. 시트 원본은 비공개이며 공개 점수 API는 닉네임·점수·완료 결과를 제공합니다. 본인 인증이 없는 연습용 랭킹이라 실제 이름 대신 서로 다른 별명을 사용합니다.

2026-10-09의 앞선 3등급 배포본에서 경험 엔진 **72개**, 전신 기하·승인 사진 **23개**, 저장 연결 **51개**, 서버 **30개**, 연결·서버 결합 **2개** 검사를 각각 통과했습니다. 실제 Apps Script 버전3와 시트14열에서 합성 시험 참가자의 기본700 + 이벤트60 + 전신300 = **1060점**과 랭킹 표시를 대조했습니다. 다른 등급100으로 중복 전송해도 최초300점·최종합계·갱신시각이 유지됐고, 기존 참가자 기록도 보존됐습니다. 이 시험에는 카메라를 사용하지 않았습니다. ISO와 GMT+0900 시각 문자열의 형식 차이는 같은 시각으로 변환해 비교했습니다. 승인된 AI 사진 7장은 각각의 목표 판정을 통과했고 꽃받침의 손목 매칭은 영상 비율에 맞는 픽셀 거리로 보완했습니다. 정적 AI 사진 분석과 VM 검사는 실제 사람의 자세 인식률이나 휴대폰 성능을 나타내지 않습니다.

새 7등급 버전은 경험 엔진 **87개**, 전신 기하·승인 사진 **33개**, 저장 연결 **59개**, 서버 `08-seven-grade.gs` **34개**, 저장 연결과 서버의 VM 결합 **4개** 검사를 통과했습니다. 기존과 같은 엔드포인트에 Apps Script 버전4를 배포한 뒤, 실제 클라우드 합성 시험 참가자 `전신시험85e6c13c`의 기본700 + 이벤트60 + 전신700 = **1460점**과 랭킹을 확인했습니다. 전신400으로 다시 보내도 최초700점·합계·갱신시각이 유지됐고, 기존 참가자 6행의 값은 모두 보존됐습니다. 이 시험 역시 카메라 없는 저장·랭킹 시험입니다. 새 제목·썸네일·양손 꽃피우기 안내·7등급 화면을 GitHub Pages에 게시했고, 공개 파일 19개의 실제 HTTPS 응답이 Git 저장 내용과 일치했습니다. 공개 브라우저에서 제목·사진 썸네일7개·1460점 랭킹·푸터를 확인했습니다. 새 버전의 실제 휴대폰 자세 인식은 아직 미검증입니다.

앞선 이벤트 보너스 버전의 실제 Apps Script·Google Sheets에서는 가명 시험 참가자의 기본 200점 + 이벤트 10점 = 최종 210점과 랭킹 1위를 확인했습니다. 같은 미션 재전송에도 점수와 갱신시각이 유지되었습니다. 이는 합성 성공 결과를 전송한 저장·랭킹 시험이며 전신 보너스 시험은 아닙니다. 더 앞선 버전에서는 저장 버튼부터 같은 시험 화면 랭킹까지 6.79·7.98·7.56초, 다른 탭에서 새 참가자 관찰까지 4.50초가 걸렸습니다. 이 시간은 이번 전신 보너스·새 화면 버전의 지연 측정값이 아닙니다.

앞선 GitHub Pages 배포와 실제 HTTPS 화면의 랭킹 조회를 확인했고, 사용자는 휴대폰에서 카메라 영상이 나오는 것을 확인했습니다. 이번 새 화면의 7+1단계 자동 진행, 실제 사람의 2초 유지·전신 등급, 사슴뿔·코·볼터치와 연결선 위치, 모바일 성능은 추가 휴대폰 시험이 필요합니다.

## 업로드할 파일

GitHub 저장소의 첫 화면에서 다음 파일이 바로 보이도록 올립니다. `pose-mission-gemini` 폴더를 통째로 한 단계 더 감싸서 올리지 않습니다.

```text
index.html
experience.js
sheets-sync.js
guide.js
assets/
  book-cover.jpg
photos/
  big-v-v2.png
  heart-v2.png
  victory-v2.png
  thumb-up-v2.png
  flower-v2.png
  hero-v2.png
  dab-v2.png
hints/
  big_v.svg
  heart.svg
  victory.svg
  thumb_up.svg
  flower.svg
  hero.svg
  dab.svg
.nojekyll
README.md
```

`index.html`은 웹페이지와 인식 기본 코드, `experience.js`는 사진 예고·자동 진행·전신 보너스·경과 시간·카메라·AR·예비 연습, `sheets-sync.js`는 저장 큐·영수증·랭킹 연결, `guide.js`는 매뉴얼과 사진 캐러셀, `assets/`는 책 표지, `photos/`는 승인된 AI 생성 포즈 사진입니다. `hints/`에는 기본 미션 SVG 7개만 올립니다. 전신은 문장으로 안내하며 사용하지 않는 `body_bonus.svg`는 로컬 원문에만 보존합니다. 공개 파일은 위 목록의 총 21개입니다. `.nojekyll`은 별도 Jekyll 처리를 건너뛰도록 두는 빈 파일입니다. **`preview-server.mjs`, `versions/`, `backend/`는 로컬 확인·원문·설치 이력용이므로 앱 공개 파일에 포함하지 않습니다.** 브라우저의 파일 업로드는 `.gitignore`만으로 제외되지 않으니 선택한 파일을 직접 확인합니다.

개인정보, 실제 참가 기록, Google Sheets 원본·내보내기 파일, OAuth 토큰·비밀키·`.env`는 올리지 않습니다. 시트 연결이 추가된 뒤에도 공개 파일에 비밀값을 넣지 않습니다.

## GitHub Pages로 직접 게시하기

1. GitHub에서 사용할 전용 저장소를 엽니다. 새 저장소가 필요하면 승인된 계정·공개 범위로 만듭니다. GitHub Free에서 Pages를 사용하려면 공개 저장소가 필요합니다. [GitHub 공식 생성 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)
2. **Add file → Upload files**에서 위 파일을 올립니다. `assets/`·`photos/`·`hints/` 폴더 구조도 유지합니다. **Commit changes**로 저장한 뒤, `main` 브랜치 첫 화면에 `index.html`과 세 폴더가 있는지 확인합니다.
3. 저장소의 **Settings → Pages**를 엽니다. Settings가 안 보이면 해당 저장소를 관리할 권한부터 확인합니다.
4. **Build and deployment → Source**를 **Deploy from a branch**로 고릅니다.
5. **Branch: main**, **Folder: /(root)**를 선택하고 **Save**를 누릅니다. 이 설정 순서는 [GitHub 공식 게시 소스 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 따릅니다.
6. 게시 처리가 끝나면 Pages에 표시된 **Visit site**로 엽니다. 바로 보이지 않으면 **Actions**에서 게시 작업의 완료·오류를 확인합니다. 변경 반영에는 최대 약 10분이 걸릴 수 있습니다. [공식 확인 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)
7. 실제 주소에서 닉네임 입력 → 게임 시작 → 카메라 허용 → 약 2초 사진·관절 힌트 예고 → 기본 포즈 2초 유지 → 다음 미션 자동 진행 → 7개 완료 뒤 전신 보너스의 문장 안내 → 전신 자세 2초 유지 → 결과 화면을 확인합니다. 사진 7개와 기본 힌트 SVG 7개, 전신 등급과 최저 등급 확정, 경과 시간, 장식 켜기·끄기, 저장 상태와 시작·결과 화면의 랭킹도 확인합니다. 문장을 수정해 커밋한 뒤 게시 주소에 반영되는지도 봅니다.

Pages는 정적 파일을 게시하고 저장 서버는 Apps Script에서 실행합니다. 개인 실습용으로 복사할 때는 자신의 결과 시트에 서버 코드를 설치·웹 앱 배포한 뒤 `sheets-sync.js` 상단의 `SHEETS_WEB_APP_URL`을 자신의 배포 주소로 바꿉니다. 성공 흐름은 **미션 성공·다음 미션 자동 진행 → Sheets 점수 갱신 → 저장 영수증 확인 → 시작·결과 화면에서 참가자 랭킹 조회**입니다. 게임 중에도 저장 큐는 계속 처리하지만 랭킹 조회는 쉽니다. 시작·결과 화면의 랭킹은 한 번의 요청이 끝난 뒤 약 5초 후 다시 읽으므로 실제 반영 지연에는 통신·실행시간이 더해집니다.

## 결과 시트의 14열

서버는 지정한 `결과` 탭의 헤더를 검사합니다. 기존 11열·13열 형식도 읽을 수 있으며 새 점수 저장은 14열 준비 후에만 수행합니다. 관리자가 `initializeBonusColumns()`를 수동 실행하면 13열에서는 N1만, 11열에서는 L1:N1 헤더만 추가합니다. 기존 참가자 행과 A:M 값은 초기화하거나 다시 쓰지 않습니다. 새 탭을 자동으로 만들거나 기존 미션에 보너스를 소급 적용하지 않습니다.

| 열 | 헤더 | 기록하는 값 |
| --- | --- | --- |
| A:B | 도전ID, 닉네임 | 참가 도전과 별명 |
| C:I | 큰 V부터 가벼운 댑까지 7개 미션 | 미션마다 한 번 100점. 화면의 ‘양손 꽃피우기’도 기존 `꽃받침` 열 사용 |
| J | 총점 | 기본 점수 합계, 최대 700점 |
| K | 갱신시각 | 새 기본 미션 또는 최초 전신 보너스가 저장된 시각 |
| L | 이벤트보너스 | 기본 미션의 이벤트 보너스 누적, 규약 상한 210점 |
| M | 최종합계 | 기본 점수 + 이벤트 보너스 + 전신 보너스 |
| N | 전신보너스 | 기본 7개 완료 후 최초 확정한 100~700점의 7등급, 미완료는 0 또는 빈칸 |

기존 행에서 L이나 N이 없거나 비어 있으면 해당 보너스는 0점으로 읽습니다. 최종 합계는 C:I의 기본 점수와 유효한 L·N에서 계산하므로 J·M의 값을 그대로 신뢰하지 않습니다. 이미 성공한 기본 미션을 다시 보내거나 전신을 다른 등급으로 다시 보내도 해당 행의 점수·보너스·갱신시각을 바꾸지 않습니다. 전신 영수증은 저장된 최초 등급을 반환하므로 앱의 예상 점수가 달랐을 때 정정할 수 있습니다. API의 `baseScore`는 기본 점수, `eventBonusScore`는 L, `bodyBonusScore`는 N, `bonusScore`는 L+N, `totalScore`는 기본+L+N입니다. 경과 시간은 이 시트에 기록하지 않습니다.

## 생성 원문과 후속 보완

실제 Gemini 대화·프롬프트·응답과 조립 이력은 비공개 `versions/`에 보존합니다. Gemini 25는 빨간 얼굴 장식, 26은 사진·힌트 예고 화면, 27은 그 화면의 CSS 수정 응답입니다. 이 응답들을 기본 앱에 조합했으며 전체 앱을 Gemini가 한 번에 완성했다고 설명하지 않습니다.

Codex는 전신 보너스 판정과 2초 구간의 최저 등급 처리, 경과 시간 표시, 꽃받침의 픽셀 거리 보완, 얼굴 캔버스 상태 보호와 카메라 취소 경쟁 상태를 후속 보완했습니다. 힌트 SVG는 실제 승인 사진 분석 좌표를 Codex 도구로 그렸고 전신 SVG는 개념 그림으로 만들었습니다. 앞선 저장 연결 `24-sync-codex-candidate.js`와 서버 `07-codex-bonus-candidate.gs`를 보존하고 7등급 서버는 `08-seven-grade.gs`로 구분했습니다. 이번 제목·썸네일·이름·7등급 변경부터는 사용자가 Gemini 추가 질문 없이 GitHub 코드를 직접 수정하도록 승인했습니다. 실제 작업은 로컬 파일과 GitHub CLI/API를 사용하며 GitHub 웹 편집기의 클릭 시연은 별도 촬영 대상으로 구분합니다. 이 비공개 원문·후보·설치 이력은 공개 앱 파일에 올리지 않습니다.

## 연수 영상 2편 구성

1편은 Gemini에 쉬운 첫 프롬프트 입력 → AI 사진 7개 승인 → 웹앱 제작 → Google Sheets 저장·실시간 랭킹 연결을 다룹니다. 2편은 파일을 GitHub에 저장 → GitHub Pages 배포 → GitHub에서 안내 문구 수정 → Commit → 공개 주소와 휴대폰 반영 확인으로 이어집니다. 원래 제작 대화와 직접 코드 수정의 출처를 구분하고 실제 촬영되지 않은 클릭·사람 인식은 시연 완료로 소개하지 않습니다. v4 대본·실습TXT·캡처계획은 기존 자료와 별도로 보관합니다.

## 아직 확인할 것

실제 GitHub 업로드와 Pages 배포는 GitHub CLI와 공식 REST API로 수행했습니다. 게시 소스는 `main`/`(root)`이며 HTTPS 강제가 켜져 있습니다. 위 브라우저 업로드·Settings 경로는 따라 하기 안내이며, 연수자료 2부에 넣을 실제 클릭 시연 화면은 별도 확보해야 합니다. GitHub 웹 편집 시연은 소유자 계정 로그인 대기 상태로, 실제 웹 수정·Commit 완료로 소개하지 않습니다. 404·사진 누락은 파일 경로·대소문자를 확인합니다.

현재 노트북에는 카메라가 없습니다. 휴대폰의 카메라 표시 성공은 사용자에게 확인받았으며, 새 버전은 휴대폰 Safari/Chrome에서 기본 7개·전신 1개 미션의 2초 유지, 전신 100~700점 7등급과 최저 등급 확정, 이벤트 보너스, 자동 진행, 경과 시간, 마지막 결과와 시트 반영을 다시 확인합니다. 세로·가로 회전, 사슴뿔·빨간 코·볼터치와 몸 연결선의 위치, 장식 토글, 일시정지·복귀, 모바일 처리 속도도 확인 대상입니다. 실제 사람의 양손 꽃피우기(기존 꽃받침) 인식과 실패 원인도 추가 관찰해야 합니다. 두 기기 동시 사용과 서버 결과 조작 방지는 검증된 것으로 소개하지 않습니다. 서버는 브라우저가 보내는 성공 결과를 수용하므로 경쟁·평가용 인증 시스템을 제공하지 않습니다.
