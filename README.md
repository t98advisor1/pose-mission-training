# 포즈 미션 · Gemini와 Google Sheets

Gemini에서 실제 생성한 HTML·JavaScript와 수정 응답을 조립한 교원연수용 앱입니다. 최종 카메라 취소 처리의 세 가지 경쟁 상태는 Codex가 후속 보완했으며 생성 원문과 보완 이력을 구분해 보존했습니다. 승인한 AI 생성 사진과 MediaPipe PoseLandmarker·GestureRecognizer로 큰 V·머리 위 하트·한손 브이·엄지척·꽃받침·슈퍼히어로·가벼운 댑 7개 미션에 도전합니다. 자세를 연속 2초 유지하면 미션마다 한 번 기본 100점을 주고 자동으로 다음 미션으로 넘어갑니다.

각 포즈 사진을 크게 약 1초 보여 준 뒤, 휴대폰 세로 화면과 컴퓨터 가로 화면에 맞춘 큰 카메라 영역에서 진행합니다. 위쪽에는 이모지와 짧은 포즈 안내가 나오고, 몸을 찾으면 파란 연결선, 목표 자세와 일치하면 초록 연결선과 유지 시간이 표시됩니다. 얼굴을 따라 움직이는 딸기 코 🍓와 꼬깔모자는 장식 버튼으로 켜고 끌 수 있습니다. 사진 다시 보기와 일시정지도 제공합니다. 실시간 명예의 전당은 시작 화면과 결과 화면에서 확인합니다.

기본 점수는 최대 700점입니다. 새 미션 성공에는 25% 확률로 10·20·30점의 이벤트 보너스가 붙도록 서버가 도전ID와 미션 이름으로 계산합니다. 같은 미션을 다시 보내도 점수와 보너스를 더하지 않습니다. 앱은 성공 직후 기본 점수와 예상 보너스를 보여 주며, 저장 완료는 Google Apps Script의 영수증을 확인한 뒤 표시합니다. 랭킹은 서버가 계산한 닉네임별 최고 최종 합계 점수를 읽습니다.

카메라 영상·촬영 사진·인식한 관절 좌표는 저장하거나 서버로 보내지 않습니다. 딸기 코와 모자도 기기 안에서 카메라 화면에만 그립니다. 전송 항목은 도전ID·닉네임·미션 이름 세 가지이며, 시트에는 미션별 점수·기본 점수·이벤트 보너스·최종 합계·갱신시각을 기록합니다. 저장 대기 결과는 브라우저에 보관해 재시도합니다. 시트 원본은 비공개이며 공개 점수 API는 닉네임·점수·완료 결과를 제공합니다. 본인 인증이 없는 연습용 랭킹이라 실제 이름 대신 서로 다른 별명을 사용합니다.

2026-10-09 기준 최종 저장 연결 모듈의 독립 VM 계약 테스트 31개와 보너스를 포함한 서버 VM 테스트 17개를 통과했습니다. 포즈·카메라·자동 진행의 경험 엔진 검증은 별도 검증 결과를 참조합니다. **이 검사는 사람의 자세 인식률이나 실제 휴대폰 성능을 나타내지 않습니다.**

실제 Apps Script·Google Sheets에서는 기존 시험 참가자 `연수시험나`의 기본 200점 + 보너스 10점 = 최종 210점과 랭킹 1위를 확인했습니다. 같은 미션 재전송에도 점수와 갱신시각이 유지되었습니다. 이는 합성 성공 결과를 전송한 저장·랭킹 시험입니다. 앞선 버전에서는 저장 버튼부터 같은 시험 화면 랭킹까지 6.79·7.98·7.56초, 다른 탭에서 새 참가자 관찰까지 4.50초가 걸렸습니다. 이 시간은 이번 보너스·새 화면 버전의 지연 측정값이 아닙니다.

GitHub Pages 배포와 실제 HTTPS 화면의 랭킹 조회를 확인했고, 사용자는 휴대폰에서 카메라 영상이 나오는 것을 확인했습니다. 새 화면의 자동 진행, 실제 사람의 7개 포즈 성공, 딸기 코·모자와 연결선의 위치, 모바일 성능은 추가 휴대폰 시험이 필요합니다.

## 업로드할 파일

GitHub 저장소의 첫 화면에서 다음 파일이 바로 보이도록 올립니다. `pose-mission-gemini` 폴더를 통째로 한 단계 더 감싸서 올리지 않습니다.

```text
index.html
experience.js
sheets-sync.js
photos/
  big-v-v2.png
  heart-v2.png
  victory-v2.png
  thumb-up-v2.png
  flower-v2.png
  hero-v2.png
  dab-v2.png
.nojekyll
README.md
```

`index.html`은 웹페이지와 인식 기본 코드, `experience.js`는 사진 예고·자동 진행·카메라 화면·연결선·AR 장식, `sheets-sync.js`는 저장 큐·영수증·랭킹 연결, `photos/`는 승인된 AI 생성 포즈 사진입니다. `.nojekyll`은 별도 Jekyll 처리를 건너뛰도록 두는 빈 파일입니다. **`preview-server.mjs`, `versions/`, `backend/`는 로컬 확인·원문·설치 이력용이므로 앱 공개 파일에 포함하지 않습니다.** 브라우저의 파일 업로드는 `.gitignore`만으로 제외되지 않으니 선택한 파일을 직접 확인합니다.

개인정보, 실제 참가 기록, Google Sheets 원본·내보내기 파일, OAuth 토큰·비밀키·`.env`는 올리지 않습니다. 시트 연결이 추가된 뒤에도 공개 파일에 비밀값을 넣지 않습니다.

## GitHub Pages로 직접 게시하기

1. GitHub에서 사용할 전용 저장소를 엽니다. 새 저장소가 필요하면 승인된 계정·공개 범위로 만듭니다. GitHub Free에서 Pages를 사용하려면 공개 저장소가 필요합니다. [GitHub 공식 생성 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)
2. **Add file → Upload files**에서 위 파일을 올립니다. `photos/` 폴더 구조도 유지합니다. **Commit changes**로 저장한 뒤, `main` 브랜치 첫 화면에 `index.html`과 `photos/`가 있는지 확인합니다.
3. 저장소의 **Settings → Pages**를 엽니다. Settings가 안 보이면 해당 저장소를 관리할 권한부터 확인합니다.
4. **Build and deployment → Source**를 **Deploy from a branch**로 고릅니다.
5. **Branch: main**, **Folder: /(root)**를 선택하고 **Save**를 누릅니다. 이 설정 순서는 [GitHub 공식 게시 소스 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)를 따릅니다.
6. 게시 처리가 끝나면 Pages에 표시된 **Visit site**로 엽니다. 바로 보이지 않으면 **Actions**에서 게시 작업의 완료·오류를 확인합니다. 변경 반영에는 최대 약 10분이 걸릴 수 있습니다. [공식 확인 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)
7. 실제 주소에서 닉네임 입력 → 게임 시작 → 카메라 허용 → 약 1초 사진 예고 → 포즈 2초 유지 → 성공과 다음 미션 자동 진행 → 결과 화면을 확인합니다. 7개 사진, 장식 켜기·끄기, 저장 상태와 시작·결과 화면의 랭킹도 확인합니다. 문장을 수정해 커밋한 뒤 게시 주소에 반영되는지도 봅니다.

Pages는 정적 파일을 게시하고 저장 서버는 Apps Script에서 실행합니다. 개인 실습용으로 복사할 때는 자신의 결과 시트에 서버 코드를 설치·웹 앱 배포한 뒤 `sheets-sync.js` 상단의 `SHEETS_WEB_APP_URL`을 자신의 배포 주소로 바꿉니다. 성공 흐름은 **미션 성공·다음 미션 자동 진행 → Sheets 점수 갱신 → 저장 영수증 확인 → 시작·결과 화면에서 참가자 랭킹 조회**입니다. 게임 중에도 저장 큐는 계속 처리하지만 랭킹 조회는 쉽니다. 시작·결과 화면의 랭킹은 한 번의 요청이 끝난 뒤 약 5초 후 다시 읽으므로 실제 반영 지연에는 통신·실행시간이 더해집니다.

## 결과 시트의 13열

서버는 지정한 `결과` 탭의 헤더를 검사합니다. 기존 11열 형식도 읽을 수 있으며, 보너스를 사용하려면 기존 A:K를 보존하고 L:M 두 헤더를 추가합니다. 새 탭을 자동으로 만들거나 기존 미션에 보너스를 소급 적용하지 않습니다.

| 열 | 헤더 | 기록하는 값 |
| --- | --- | --- |
| A:B | 도전ID, 닉네임 | 참가 도전과 별명 |
| C:I | 큰 V부터 가벼운 댑까지 7개 미션 | 미션마다 한 번 100점 |
| J | 총점 | 기본 점수 합계, 최대 700점 |
| K | 갱신시각 | 새 미션이 저장된 시각 |
| L | 이벤트보너스 | 서버가 누적한 보너스, 최대 210점 |
| M | 최종합계 | 기본 점수 + 이벤트 보너스, 최대 910점 |

기존 행에서 L:M이 비어 있으면 보너스는 0점, 최종 합계는 기존 기본 점수로 취급합니다. 이미 성공한 미션을 다시 보내면 해당 행의 점수·보너스·갱신시각을 바꾸지 않습니다. 참가자가 클라이언트에서 보낸 점수나 보너스 값을 저장하는 방식은 사용하지 않습니다.

## 아직 확인할 것

실제 GitHub 업로드와 Pages 배포는 GitHub CLI와 공식 REST API로 수행했습니다. 게시 소스는 `main`/`(root)`이며 HTTPS 강제가 켜져 있습니다. 위 브라우저 업로드·Settings 경로는 따라 하기 안내이며, 연수자료 2부에 넣을 실제 클릭 시연 화면은 별도 확보해야 합니다. 404·사진 누락은 파일 경로·대소문자를 확인합니다.

현재 노트북에는 카메라가 없습니다. 휴대폰의 카메라 표시 성공은 사용자에게 확인받았으며, 새 버전은 휴대폰 Safari/Chrome에서 7개 미션의 2초 유지·기본 100점·보너스·자동 진행·마지막 결과와 시트 반영을 다시 확인합니다. 세로·가로 회전, 딸기 코·모자와 몸 연결선의 위치, 장식 토글, 일시정지·복귀, 모바일 처리 속도도 확인 대상입니다. 두 기기 동시 사용과 서버 결과 조작 방지는 검증된 것으로 소개하지 않습니다. 서버는 브라우저가 보내는 성공 결과를 수용하므로 경쟁·평가용 인증 시스템을 제공하지 않습니다.
